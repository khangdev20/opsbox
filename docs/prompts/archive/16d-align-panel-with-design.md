# 16d. Align the Linux panel with the design

Files: `web/css/app.css`, `web/js/shell.js`, `web/js/ui.js`, `web/js/pages/*.js`, `web/index.html`, `web/kit.html`, new `web/img/` for the logo. Source of truth: `design/project/*.dc.html` (generated by `design/gen.py` and `design/pages2.py` to `pages6.py`; the tokens and component markup are easiest to read in `gen.py`). The owner reviews the design in the canvas artifact; when the rendered canvas and the generator disagree, ask, otherwise follow `gen.py`.

Goal: the running panel looks like the design, screen by screen, in both themes and on mobile, without breaking behaviour or the polish from 16b. Presentation only: no API changes, no new features. If the design shows something the backend does not support, do not fake it; list it as a gap in `docs/STATUS.md`.

## 0. Side-by-side baseline
- Write `design/preview.py` (Playwright, dev only): for each board, load the `.dc.html` file with `{{theme}}` set to dark and to light and the theme variables injected, and save a 1440 px wide PNG to `docs/screenshots/design/<Board>-<theme>.png`. Where `sc-if` blocks or other template parts do not render statically, note it and read `gen.py` for that part.
- Screenshot the same screens of the running panel on `opsbox-vm` (logged in, real data) to `docs/screenshots/16d/before/`.
- Make a table in `docs/STATUS.md`: board → page module → differences found (layout, spacing, type, colour, components, missing states). Work through it in order of visibility: shell first, then Overview, then the rest.

## 2. Recent design changes the panel does not have yet
These were made in the canvas on 2026-11-18. Check each one explicitly:
- **Logo**: the OpsBox mark (`design/project/assets/logo-mark-*.png`, copy to `web/img/`) followed by the wordmark "Ops" in the text colour and "Box" in `#FC5801`, Geist 700. It replaces `opsbox<i>_</i>` in the top bar, login, setup and recovery screens. Add the favicon (`<link rel="icon">`, 64 px and 256 px PNG; an `apple-touch-icon` too). Other text that says "opsbox" stays as it is.
- **Sidebar groups**: Overview on top, then labelled groups Deploy (Apps, Containers), Server (System, Terminal, Files, Cleanup), Protect (Backups, Alerts, Security). Group labels are small uppercase muted text; when the sidebar is collapsed they become thin dividers. Pages the design does not list (Access, Settings, databases) go where `nav2` puts them today, or into the account menu below; do not drop any route.
- **Collapse button at the bottom of the sidebar**: full-width row under a divider with the panel icon and "Collapse"; icon only, rotated, when collapsed. Remove the button from the top of the sidebar. Keep the saved state in `localStorage` and the keyboard shortcut if there is one.
- **Account menu in the header**: replaces "admin · sign out" and the separate Settings link. A pill button with initials avatar, user name and role, and a chevron; it opens a menu with name, username, role and 2FA state, then Profile and security, Server settings, API tokens, a divider, and Sign out in the danger colour. Real data from the session; menu closes on Escape, outside click and route change; arrow keys move between items (`role="menu"`).
- **Overview layout**: a 6 column grid with 24 px gaps under the KPI strip (which also uses 24 px gaps). Row 1: CPU and memory chart (3 columns, chart 300 px tall, legend with current values plus average and peak) and Top processes (3 columns). Row 2: Containers, Reclaimable space, Recent activity (2 columns each). Section headers share one minimum height so titles line up. Collapse to one column on narrow screens.
- **Top processes**: "● live" badge, CPU / Memory sort switch, "All →" link to System, a "Heaviest right now" highlight strip, rows with rank, coloured initial tile, name with type and PID, CPU bar in the accent colour and memory bar, and a "this" badge on opsbox's own process. The sort switch must really sort the data the API returns.
- **Select**: no native arrow; a thin chevron 12 px from the right edge, hover and focus states as in `gen.py` (search for `select{{-webkit-appearance`).
- **Checkbox and radio**: 7 px radius, 1.5 px border, accent fill with a white check when checked, soft hover halo, press scale, accent focus ring; radio with a thick accent ring when checked. Reduced motion turns the transitions off.

- **Containers table (exception, panel is the source of truth)**: redesigned directly in the panel on 2026-11-19: one Container column (name, managed tag, short image `name:tag` with the full reference on hover), state, CPU, Memory, port chips, and a single row of icon actions (Logs, Inspect, Restart/Start, Stop/Delete) with tooltips. Keep it; do not revert to the design board. Reuse its `iconAct` pattern for other tables with row actions (Apps, Backups, Images, Volumes) if they have the same wrapping problem.

If 16b already added equivalents, unify them with the design rather than keeping two versions.

## 3. Then everything else, screen by screen
For each row of the table: match spacing, font sizes and weights, colours (use the existing tokens; add a token instead of a literal colour), radii, borders, empty, loading and error states, and icon use. Keep the 16b motion and live-update behaviour. Fix differences in shared components (`ui.js` helpers and CSS classes) rather than per page, so every page benefits.

## Rules
- Tokens and components in one place in `app.css`; no inline styles in page modules except computed values (widths of bars and similar).
- Both themes, 1440 px and 390 px widths, keyboard navigation and visible focus, WCAG AA contrast.
- Keep `data-act` wiring, routes and API calls as they are. `web/kit.html` shows any new or changed component (account menu, sidebar groups, top-process row).
- No copied assets from other products; only the OpsBox logo files from `design/`.

## Done when
- The table in `docs/STATUS.md` has no open visual differences, or each remaining one is explained (backend gap or deliberate).
- After screenshots in `docs/screenshots/16d/after/`, same screens and themes as the before set.
- Tests and CI green; a quick manual pass on `opsbox-vm` through every page with no console errors.

Out of scope: `site/` (landing page), new features or endpoints, changes to the design files themselves (if the panel suggests a better solution, note it in STATUS for the owner).

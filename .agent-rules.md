# AGENT ORCHESTRATION RULES & EXECUTION WORKFLOW
# Last updated: 2026-11-19

## 1. Core Architecture & Roles
- **Orchestrator (Coordinator)**: Exclusively uses **Gemini**.
  - Responsibilities: Task planning, step-by-step sequencing, dependency management, error catching, automatic retries, and final synthesis.
- **Worker Subagents (Internal)**: Exclusively uses **Claude**.
  - Model range: **Claude Opus 5.5 High (Max)** down to **Claude Sonnet 5.5 Medium (Min)**.
  - Never use Gemini models for subagents (Gemini is strictly reserved for coordination).
- **External CLI Agents**:
  - **Claude Code CLI** (`claude -p "..."`): Located at `/Users/lenhutkhangvo/.local/bin/claude`.
  - **Codex CLI** (`codex exec "..."`): Located at `/opt/homebrew/bin/codex`. Model restricted to **6-sol medium**.
  - *(Cursor CLI has been removed from the orchestration pipeline)*.

## 2. Task Allocation & Priority Matrix

### Priority 1: Primary Development & Complex Tasks -> Claude
- **Scope**:
  - All prompt execution, feature implementation, architectural refactoring.
  - Bug fixes, unit/integration test creation, UI adjustments, API handlers.
  - Deep-reasoning and multi-module coordination.
- **Execution Channels**:
  - **External CLI**: `claude -p "<prompt>"`
  - **Internal Subagent**: `claude-opus-5-5-high`, `claude-opus-5-5-medium`, `claude-sonnet-5-5-high`, or `claude-sonnet-5-5-medium`.

### Priority 2: Secondary / Verification & Fallback -> Codex CLI
- **Model Rule**: Strictly fixed to **6-sol medium** (via `-m` flag).
- **Scope**: Automated code review (`codex review`), secondary fallback, independent second-opinion verification, or when Claude hits session limits.

---

## 3. Error Recovery & Retry Strategy

1. **Retry Limit**: Maximum 2 to 3 retries per task before escalating.
2. **Execution Failure (Exit code != 0, test failure, syntax error)**:
   - Orchestrator inspects `stderr`, error trace, and current `git diff`.
   - Orchestrator generates a self-correction prompt containing exact error logs and file context.
   - Re-runs task with the corrected prompt.
3. **Failover (Fallback Chain)**:
   - If Claude encounters rate-limit/session exhaustion -> Fallback to **Codex (6-sol medium)**.
4. **Transient Errors (Network, Timeout, Rate-limit)**:
   - Apply exponential backoff (wait 3s, 7s, 15s) and retry.

---

## 4. Execution Workflow Pipeline

1. **Intake & Assessment**: Orchestrator parses task/prompt requirements.
2. **Dispatch**:
   - Send directly to **Claude** (CLI or Subagent).
3. **Verification**:
   - Run tests, check formatting (`cargo fmt`, `clippy`), verify functionality.
4. **Completion & Archival**:
   - Update `STATUS.md` and `README.md`.
   - Commit & push/tag as required.
   - Archive completed prompt file to `docs/prompts/archive/`.
